# Code map: root

Repo root: README, docker compose files, scripts/, config and top-level docs.

- README.md, HANDOFF.md, BACKLOG.md: project overview and demo; remaining planning context and open decisions; Portainer features not yet planned as beads
- CLAUDE.md, AGENTS.md: agent instructions (project rules, beads workflow)
- docs/code-map/: folder code map: `index.md` with rules and path prefix table, one file per module, checked by `.claude/scripts/code-map-check.mjs`
- docs/sous-handoff.md: Sous Factory trial versus `/next-task*`: setup, runs, comparison, decision
- docs/images/*: README screenshots and deploy-flow GIF, generated by `frontend/e2e/screenshots/capture.ts`
- docker-compose.dev.yml: local PostgreSQL 16 for development (healthcheck, `DB_*` from `.env`)
- docker-compose.yml: hosting stack: backend and frontend images (GHCR or local build), external PostgreSQL, Docker socket, only the frontend port published
- docker-compose.demo.yml: throwaway demo stack with seed data and public demo passwords, not for real use
- .env.example: documents the `.env` variables: `DB_*`, initial admin password, `DOCKER_GID`, encryption key, image tag and port, exec and OIDC options (`.env` is gitignored)
- renovate.json: Renovate dependency update config
- .gitignore: repo-wide ignore rules (env file, build output, local tooling state)
- scripts/{backup.sh,restore.sh,backup-restore.test.sh}: hosting backup (DB dump plus stacks and volume-backups volumes), restore into an empty setup, shell test with stubbed tools
- scripts/{check-template-images.sh,check-template-data-paths.sh}: read-only checks that every `apps.json` template image exists and mounts its declared volumes
